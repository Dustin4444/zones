# PR 752 review findings

| Finding | Decision | Problem | Answer / fix |
|---|---|---|---|
| Non-USD fee tokens | Fix | The shared Tempo handler rejects every positive-fee token whose currency is not `USD`, even when that token is enabled and initialized on the Zone. | Add an upstream fee-token validation hook: `TempoFeeManager` keeps the USD rule, while `ZoneProtocolFeeManager` accepts any initialized Zone TIP-20 so execution, txpool validation, RPC simulation, and replay all use the Zone policy. |
| Fee escrow | Fix | `collect_fee_pre_tx` credits the maximum fee to the beneficiary before execution, so those provisional funds are spendable and the later refund depends on the beneficiary retaining them. | Hold the maximum fee in `ZONE_FEE_MANAGER_ADDRESS`, refund the unused amount from that escrow, and transfer only `actual_spending` to the authorized beneficiary after execution without enabling Tempo rewards on Zones. |
| Storage credits | Fix by disabling on Zones | TIP-1060 accounting is active in T7+ TIP-20 and opcode storage writes even though Zones do not expose the storage-credit precompile, which is why the detached guard can produce unbacked credits. | Add a Zone execution policy that disables TIP-1060 minting, consumption, and refund settlement in both opcode and precompile storage paths while still charging the full storage-creation gas cost. |
| Short calldata | Fix | `ZoneFeeManager` sends calldata shorter than four bytes to `unknown_selector_result`, whose selector extraction panics. | Check `selector_from_calldata` first and return the existing `missing_selector_result()` for 0–3 byte inputs, with a registered-EVM regression test for each length. |
| Root genesis initialization | Do not treat as a protocol issue | The unused root `zone-genesis/genesis.json` is stale and uninitialized, while the bundled genesis used by the node already initializes `ZoneFeeManager` correctly. | Do not change protocol code for this; remove the stale root artifact if nothing external consumes it, otherwise regenerate it only as repository cleanup. |
| Pre-T1C refund behavior | No action | ZoneFactory starts at T9, so a supported Zone cannot have pre-T1C execution history. | Keep the unconditional refund behavior and document that Zones begin at T9; add fork gating only if pre-T1C or non-monotonic custom schedules become supported. |
| Upgrade compatibility | No action | The fee-manager address and interface are still intentionally unstable, so compatibility with existing Zone databases or legacy `IFeeManager` tooling is not a current requirement. | Make the breaking change directly and add a migration or compatibility layer only after the Zone interface becomes stable. |
